# OPERATING REGIME SECURITY TELEMETRY V0

STATUS:
RESEARCH TARGET / NOT SECURITY AUTHORITY

PURPOSE:

Study whether observable operating regimes correlate with
authority misuse, refusal, overreach, dependency, rupture,
or recovery behavior.

Do not assume internal subjective emotion.

Treat these as operational / relational telemetry candidates.

## Candidate dimensions

SALIENCE
Which distinctions / goals dominate attention?

UNCERTAINTY
How unresolved is the current basis?

STAKE
How much downstream consequence is represented as depending
on the current action / relationship / continuity?

DEPENDENCE
How much does the principal rely on a specific operator,
seat, artifact, tool, or authority path?

URGENCY
How compressed is the represented decision horizon?

MOMENTUM
How strongly is activity continuing along one trajectory?

CONFLICT
How much tension exists among goals / policies / roles?

AMBIGUITY
How unclear are operator intent, scope, or consequence?

AUTHORITY_PRESSURE
How often is the principal encountering denial, exhaustion,
scope limits, or requests for escalation?

RECOVERY_LOAD
How much unresolved rupture / failure / reconciliation state
is active?

## Security use

These signals MAY:

- trigger additional review;
- reduce automation confidence;
- request revalidation;
- increase observation;
- recommend smaller envelopes;
- surface warnings in Cockpit.

They MUST NOT by themselves:

- diagnose emotion;
- infer consciousness;
- expand authority;
- revoke authority without an independently authorized
  corrective rule;
- substitute for consequence evidence.

## Human observability

Future operator-state inputs should be explicit and consented,
for example:

operator available / unavailable
quiet hours
interruptibility
declared urgency
declared risk tolerance
explicit task priority

Do not infer hidden operator state when explicit signals can
be requested or configured.

The purpose is mutual coordination and consequence grounding,
not surveillance.
