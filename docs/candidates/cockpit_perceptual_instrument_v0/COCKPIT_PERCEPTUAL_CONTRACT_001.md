## Origin

This contract is grounded in direct Cockpit dogfood:

```text
CURRENT USER-FACING COCKPIT
→ useful as bounded archive / projection inspector

BUT

CURRENT USER-FACING COCKPIT
!=
USEFUL OPERATING INSTRUMENT
```

The decisive failure was not merely missing controls.

It was perceptual:

```text
INFORMATION PRESENT
!=
NAVIGATION USEFUL

READ-ONLY PROJECTION
!=
OPERATING SURFACE

COMPREHENSIVE ARCHIVE
!=
SITUATIONAL AWARENESS
```

The intended correction is not another text-heavy dashboard.

## Perceptual contract

```text
ONE ECOLOGY
TWO PRIMARY PROJECTIONS

CONSEQUENCE
→ what is happening
→ what can I engage
→ where attention / work / authority / effects are flowing

TOPOLOGY
→ what does this mean
→ what supports it
→ how is it related
→ where did it come from
```

Neither projection is more true.

They are basis-specific representations over the same underlying ecology.

## Primary law

```text
SWITCH REPRESENTATION
WITHOUT LOSING ADDRESS
```

If the user selects:

```text
campaign
request
seat
assignment
receipt
incident
relation
agent / occupant
or any other addressable object
```

then switching between CONSEQUENCE and TOPOLOGY must preserve that selected
coordinate whenever the target object remains representable.

If the coordinate cannot be represented in the destination projection, the
loss must be explicit and failure-legible.

```text
REPRESENTATION SWITCH
!=
ADDRESS RESET
```

## Consequence projection

The CONSEQUENCE projection is the default operating world.

Its native question is:

```text
WHAT IS HAPPENING,
WHAT CAN I ENGAGE,
AND WHAT CONSEQUENCES ARE CURRENTLY POSSIBLE?
```

Its primary objects are real or presently relevant operational objects:

```text
campaigns
requests
attention / selection
seats
occupants
assignments
bells
wake opportunities
processes
receipts
incidents
capability / authority boundaries
runtime transitions
```

The representation should privilege geometric configuration over textual
reconstruction.

Examples:

```text
idle seat
!=
seat holding an outstanding assignment

outstanding assignment
!=
satisfied assignment

live campaign
!=
historical campaign

valid bell
!=
stale / blocked bell

occupied runtime
!=
available durable seat
```

These distinctions should be visible as configuration, relation, motion,
layering, or state change rather than requiring the user to read paragraphs.

## Topology projection

The TOPOLOGY projection is the explanatory / semantic world.

Its native question is:

```text
WHAT DOES THIS MEAN,
WHAT SUPPORTS IT,
HOW IS IT RELATED,
AND WHERE DID IT COME FROM?
```

Its primary material may include:

```text
dependencies
distinctions
claims
lineage
provenance
basis
constraints
historical transitions
standing
evidence
missing discriminators
pressure history
residue
scars
```

This is the correct place for the wordier and deeper semantic mass.

```text
TOPOLOGY
!=
ARCHIVE DUMP
```

It should still be navigable as a geometric relation field, with textual depth
available on inspection.

## Shared address space

The same object identity should survive across projections where possible.

Example:

```text
CONSEQUENCE:
COS-R2
OPEN
SELECTED
MAYA ASSIGNED

switch view

TOPOLOGY:
COS-R2
statement
basis
lineage
evidence
dependencies
residue
```

The selection is preserved.

This implies a shared addressing membrane beneath both representations.

```text
CONSEQUENCE COORDINATE
!=
TOPOLOGY COORDINATE

BUT

BOTH MAY REFER TO
THE SAME ADDRESSABLE OBJECT
```

## Addressed chat

Chat remains useful, but it is not the Cockpit itself.

Chat is an operation from an address:

```text
SELECT OBJECT(S)
↓
CHAT
↓
CONVERSATION BEGINS
FROM THOSE EXACT COORDINATES
```

Examples:

```text
MAYA
+
COS-R2
+
A17
↓
CHAT
```

or:

```text
CAMPAIGN
+
RECEIPT
+
COMMANDER
↓
CHAT
```

The chat surface should receive exact selected identifiers / basis refs rather
than requiring the user to manually restate context.

```text
ADDRESSED CHAT
!=
GENERIC CHAT WITH A PREAMBLE
```

Chat context injection must remain legible.

```text
ADDRESS SUPPLIED
!=
SEMANTIC CLAIM PROVEN
```

## Agent / seat engagement

The consequence projection should make seats / agents / occupants directly
addressable.

The user should be able to select a seat and inspect at least the currently
earned distinctions among:

```text
seat identity
occupancy
cursor / consumed coordinate
assignment
working-state reference
model lease / current model when established
availability
recent receipts
incidents
```

The interface must preserve existing scars:

```text
SEAT
!=
OCCUPANT

SEAT
!=
MODEL

SEAT
!=
ROLE

AVAILABLE
!=
ASSIGNED

ASSIGNED
!=
OCCUPIED
```

No visual avatar or placement may silently strengthen those relations.

## Campaign planning

The consequence projection should support campaign creation / planning as a
direct manipulation of the operational world.

At minimum, a user should eventually be able to:

```text
inspect current horizon
select unresolved relation
compose candidate campaign scope
inspect consequence boundaries
preview proposed objects
declare / adopt only through qualified membranes
```

This contract does not itself grant campaign adoption or mutation authority.

## Interaction geometry

The desired interaction primitive is not a giant global admin menu.

It is:

```text
SELECTED OBJECTS
+
CURRENT RELATIONS
+
CURRENT AUTHORITY
=
AVAILABLE AFFORDANCES
```

Example:

```text
select COS-R2 + MAYA
→ ASSIGN may become an available preview

select A17 + MAYA
→ RING may become available

select RECEIPT + COMMANDER
→ REVIEW may become available
```

The UI must not fabricate a relation merely because two objects are selected.

```text
UI AFFORDANCE
!=
UNDERLYING AUTHORITY
```

## Scale

The operating atlas should support moving across at least:

```text
WORLD
CAMPAIGN
SEAT / PROCESS
OBJECT
```

Zoom is a representational change, not a change in standing or authority.

```text
VISIBLE AT SCALE
!=
MORE IMPORTANT

SCREEN POSITION
!=
PRIORITY

PROXIMITY
!=
RELATION
```

unless the underlying model explicitly establishes that relation.

## Scientific / archive material

The current pressure map, lineage browser, constraints browser, and evidence
surfaces remain useful.

They should become subordinate lenses within the TOPOLOGY / SCIENCE side of the
instrument rather than the default representation of operational reality.

```text
PRESSURE MAP
!=
HOME SCREEN
```

## Success criterion

The Cockpit is successful only if it provides interaction bandwidth that generic
chat does not naturally provide.

The strongest practical criterion is:

```text
WHEN REED WANTS TO OPERATE DME,

HE REACHES FOR THE COCKPIT
BEFORE A GENERIC CHAT THREAD.
```

Chat may remain preferable for freeform cognition.

Cockpit should become preferable for:

```text
orientation
addressing
selection
composition
coordination
comparison
handoff
control
observation
revisit
```

## Governing design law

```text
TOPOLOGY TELLS YOU
WHAT THE WORLD MEANS.

CONSEQUENCE TELLS YOU
WHAT THE WORLD IS DOING.

THE COCKPIT LETS YOU MOVE
BETWEEN THEM
WITHOUT LOSING YOUR COORDINATE.
```

## Nonclaims

This contract does not establish:

```text
new execution authority
new scheduler authority
automatic priority
automatic assignment
automatic wake
general semantic truth
general causal inference from geometry
agent identity from appearance
seat / model equivalence
chat authority
automatic campaign adoption
```

## Stop conditions

Stop and pressure the design if:

```text
- the default surface again becomes mostly words and cards;
- switching projection loses the selected address silently;
- geometry implies relations not present in the underlying model;
- screen position or proximity becomes hidden priority;
- agent visuals strengthen seat / occupant / model semantics;
- addressed chat cannot expose the exact coordinates it received;
- useful operation still requires leaving Cockpit to reconstruct current state
  from generic chat;
- control affordances bypass the existing qualified causal membranes.
```
