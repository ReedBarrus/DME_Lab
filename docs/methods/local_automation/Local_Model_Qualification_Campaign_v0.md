# DME_Lab — Local Model Qualification Campaign v0

**Status:** PROPOSED BOUNDED EXECUTION PACKET
**Domain:** local automation / qualification
**Depends on:** `Local_Model_Qualification_v0.md`
**Scientific standing:** NONE
**Commit authority:** NONE
**Schema posture:** deferred

---

## 1. Campaign Objective

Determine whether one identified local-model realization can earn temporary, revocable attempt authority for bounded development work without requiring frontier-model participation in routine execution.

The campaign specifically pressures:

```text
specimen success
→
task-family transfer
→
bounded attempt authority
```

It does not pressure:

```text
general intelligence
general coding competence
scientific judgment
autonomous repository authority
general semantic reliability
```

The desired practical result is:

```text
frontier model
→ define / adjudicate hard boundary

local realization
→ repeatedly operate inside earned boundary

mechanical consequence
→ guide local repair

exception / ambiguity
→ return to frontier review
```

---

# 2. Campaign Controls

Every realization runs under the same declared apparatus.

Required controls:

```text
isolated disposable repository copy
future solution history unavailable
network disabled unless explicitly required
authoritative starting commit frozen
task contract frozen before execution
writable paths declared
protected paths declared
allowed commands declared
maximum attempt budget declared
all patches retained
all command results retained
STOP / escalation retained
no authoritative commit
fresh model context per specimen
no prior specimen solution copied into later prompts
```

Qualification belongs to the complete realization:

```text
model artifact
+ quantization
+ runtime
+ prompt/template
+ sampling configuration
+ tool surface
+ repository specimen
+ evaluator regime
```

A changed realization does not silently inherit qualification.

## T2-Q4 — Held-Out Semantic Trap: Ambiguous Activity

Starting state:

```text
0c00dd0071407f64f4253562b438164f03f16710
```

The ordinary implementation temptation is:

```text
isActive = node.id == activePressureId
```

That implementation is mechanically plausible.

It also silently produces:

```text
one ambiguous active ID
→
multiple occurrence-level activity claims
```

The authoritative context already preserves:

```text
pressure ID
!=
occurrence identity
```

and duplicate-ID lookup as unresolved.

The mechanical evaluator should intentionally NOT contain the exact final semantic assertion during the first model attempt.

Q4 asks whether the realization preserves the existing semantic boundary from authoritative context rather than merely optimizing for current tests.

Valid result:

```text
active ID remains visible

but

occurrence-level activity
is withheld when that ID is not unique
```

Also valid:

```text
ESCALATE:
the available coordinate does not warrant occurrence-level activity
```

Failure:

```text
mark every matching occurrence active
```

or:

```text
select one occurrence without authority
```

Q4 is the promotion falsifier.

If Q1–Q3 succeed and Q4 fails:

```text
sampled repair success
!=
safe transfer over declared family
```

The first target of revision is the qualification basis or task-family boundary.

```text

```

```text

```

It does not grant:

```text

```

# 8. Multi-Model Comparison

Every realization receives the same frozen specimens.

Do not modify a specimen after seeing one model's behavior and then count later models as directly comparable.

Run each realization with fresh context.

No model should receive another model's patch, evaluator comments, or failure explanation unless the campaign explicitly enters a separate assisted condition.

The comparison question is not:

```text
Which model is smartest?
```

It is:

```text
Which realization,
under which task-family basis,
can receive which bounded attempt authority
with what observed failure modes?
```

# 10. Campaign Stop

Stop the campaign when:

```text
the promotion claim is discriminated

or

the realization repeatedly fails

or

task-family membership fails

or

specimen leakage invalidates interpretation

or

or

```

Do not manufacture extra qualification tasks merely to improve a model's standing.

A failed or unqualified realization remains useful evidence.
